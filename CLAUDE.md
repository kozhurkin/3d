# 3d

## Сборка
- `index.html` — собранный файл: приложение `src/app.html` (с модулями `src/js/` и панелями `src/panels/`) вшито строкой в `src/shell.html`. Руками его не править: все правки только в `src/`.
- После любой правки в `src/` сразу запускать `npm run build` (или `npm run check` — он сначала собирает сам) и проверить в Node, что изменение попало в `index.html`. Пользователь смотрит результат в `index.html`.
- Проверка: `npm run check` (приложение в Node с заглушкой THREE), обвязка — `tools/smoke/harness.js`. Перед коммитом — полный прогон.
  - Части: `app`, `kitchen`, `living`, `bath`, `hall`, `flight`, `walk` — `tools/smoke/<часть>.js` или папка `tools/smoke/<часть>/` (`kitchen`, `living`, `bath`:
    файл на предмет, как в коде, `index.js` подключает их по порядку). Одна часть — `npm run check -- <часть>`, один предмет — `npm run check -- <часть>/<предмет>`.
    Одна проверка — `--grep <часть имени>` (можно вместе с частью: `npm run check -- bath --grep крышка`), список без прогона — `--list`, время каждой — `--time`.
  - Новое поведение — новые проверки в файл своего предмета (своей части).
  - Новый код для страницы — функцией: `p.run(() => tt.item('tray', 'bath').visible)`; что нужно из проверки — аргументами: `p.run((k) => …, k)`
    (функция уходит в страницу текстом и переменных проверки не видит). Старые строки `p.run('…')` переводить, когда правишь саму проверку (образец — `bath/tray.js`).
  - В коде для страницы (`p.run(...)`) — помощники `tt` (`harness.js`: `PAGE_KIT`): `tt.fur()` / `tt.fur("bath")` (мебель вида, а не `VIEWS.kitchen.furniture()`),
    `tt.item("sofa")` / `tt.item("wash","bath")`, `tt.parts(g, q=>…)`, `tt.box(ps,'xzy')`, `tt.mm(v)`, `tt.doors(g)`; обходы и min/max вручную не писать.

## Устройство
- Одна сцена квартиры, вкладки — её виды (`views.js`: `VIEWS`, `addView`, `showView`). Размеры стен — `A` в `apartment.js`, правятся только на «Планировке» (`plan.js`); комнаты берут их оттуда.
- Модули — обычные скрипты страницы с общей областью видимости, порядок — в `src/app.html`. Модули комнат (папки `src/js/rooms/<комната>/`, прихожая — `rooms/hall.js`) обёрнуты в IIFE (папку оборачивает сборка): имена внутри у них совпадают (`P`, `computeParts`, `build`…). Общее для комнат — в `rooms/common.js` (`roomKit`); правка, одинаковая для всех комнат, делается там.
- Комната «Кухня» на плане одна, но код её поделён: `rooms/kitchen/` — сама кухня у кухонной стены (шкафы, техника, обеденный стол, стулья, светильник, полки над столом), `rooms/living/` — остальное в комнате (рабочее место: письменный стол, кресло, витрина; жилая часть: шкаф, антресоли, диван, полка над ним, стеллажи). `living` грузится перед кухней, строится вместе с ней в её осях и берёт у неё нужное через `living.attach`. Обе папки — по файлу на предмет.
- Карта файлов — в README; предметы комнат — только здесь, ниже.

## Где что (предмет → файл)
- В папке комнаты: `index.js` (первым) — заголовок, `P`; `cabinets.js` — детали шкафов `computeParts`, `fromModel`, `clamp`, отделка `FIN`;
  `info.js` — карточки «i» (`INFO`); `view.js` (последним) — размерные линии, ракурсы, панель, `roomKit(…)` с `extra.items` — списком сборщиков предметов вида.
- `rooms/kitchen/`: `dining` — обеденный стол; `pendant` — светильник над ним; `chairs` — стулья BERGMUND; `shelves` — полка над столом (оливковая, трёхъярусная);
  `appliances` — мойка, варочная, посудомойка, духовка, вытяжка, холодильник.
- `rooms/living/` (без `cabinets` и `view`; `index` — что берётся у кухни, `smooth`; `api.js` последним — `living.items`, `attach`, препятствия обхода):
  `desk` — письменный стол HEMNES, надстройка, полка над ней; `chair` — кресло MILLBERGET; `macbook`; `vitrine` — витрина или книжный стеллаж;
  `wardrobe` — угловой шкаф, антресоли, зеркало, вешалка; `rack` — стеллажи; `sofa` — диван и полка над ним; `radiator` — под подоконником.
- `rooms/bath/`: `toilet` — инсталляция и унитаз; `tray` — поддон; `shower` — стойка (`buildShowerRack`);
  `curtain` — шторка; `wash` — стиральная машина, раковина над ней, шкафчик, смеситель.
- Общее для нескольких предметов комнаты (материалы, размеры) — только в `index.js` / `cabinets.js`, не в файле одного из них:
  иначе зависимость скрыта, и при перестановке файлов всё падает уже при запуске.
- Фурнитура (шкант, эксцентриковая стяжка…) — реестр `FITTINGS` в `furniture.js`; её отверстия в детали — `fittingHoles` в `holes` детали, новую — туда же.
- `rooms/hall.js` — прихожая одним файлом. Не в комнатах: стены, двери (наличники, добор), ступенька, окно — `walls.js`; общее у шкафов — `furniture.js`.

## Новый предмет
1. Файл `src/js/rooms/<комната>/<предмет>.js`: `build<Предмет>(g, opts)` сам создаёт свою группу, кладёт её в `g`, ставит `userData.<ключ>=true`
   (по ключу его находят `tt.item` и код комнаты) и `userData.info` из `info.js`; возвращает массив своих дверей (что открывается по клику), нет — `[]`.
   Ссылку на предмет в переменной модуля не держать: нужен — искать по ключу в группе (как хук кадра в `bath/view.js`).
2. Имя файла — в `data-files` комнаты в `src/app.html` (до `view` / `api`).
3. Сборщик — в список `extra.items` в `roomKit(…)` комнаты (`view.js`, у прихожей — `hall.js`); у `living` — в `living.items` в `api.js`.
4. Проверки — `tools/smoke/<комната>/<предмет>.js` (первая строка `// что (src/js/rooms/<комната>/<предмет>.js)`, `require('../harness')`), строка в её `index.js`.
5. Строка в карте выше.
