# План: одна модель квартиры для всех вкладок

## Ветка

- Вся работа идёт в ветке `single-model`; `main` не трогаем, пока перенос не закончен. Если сайт публикуется из `main` (в репозитории есть `.nojekyll`), он остаётся рабочим. Ветку пушим в `origin`, только если пользователь попросит.
- Каждый этап — отдельный коммит в ветке, с собранным `index.html`.
- Если нужна правка в нынешней версии, она делается в `main`, а затем `main` вливается в ветку (`git merge main`). `index.html` при конфликте не правится руками, а пересобирается (`npm run build`).
- Ветка вливается в `main`, когда пользователь скажет: после этапа 8 или раньше, если промежуточный вариант устроит.
- Пока переключена ветка, `index.html` в рабочей папке — версия из ветки; чтобы посмотреть текущую версию, нужно `git switch main`.

## Зачем

Сейчас каждая вкладка — отдельная страница в своём iframe ([src/shell.html](src/shell.html)) со своей сценой, своим renderer и своими стенами:

- стены планировки — список `WALLS` в координатах квартиры ([src/plan.html](src/plan.html), около строки 205);
- стены комнат построены вручную и независимо: `buildWall()` в `src/kitchen.html`, `src/bath.html`, `src/hall.html`;
- размеры дублируются и сверяются руками: `A.kW` ↔ кухня `P.W`, `A.bNiche`/`A.bL` ↔ санузел `P.W`/`P.L`, `A.hallW` ↔ прихожая `P.W`, проём входной двери `84…976` ↔ прихожая `Lw`/`Rw`;
- около 80 % кода трёх комнат совпадает дословно (742 из 894 уникальных строк прихожей есть в санузле).

Цель — одна 3D-модель квартиры (стены, проёмы, двери, окно, шкафы) в одной сцене. Вкладка — вид на эту модель со своими настройками: на «Планировке» видно всё и правятся размеры стен, во вкладке комнаты видны только её стены и правится шкаф.

## Решения (согласовано)

1. В комнатах стены **обрезаются рамкой вида**. Границы рамки настраиваются во вкладке комнаты.
2. Размеры, принадлежащие стенам, меняются **только на «Планировке»**. Во вкладке комнаты они видны, но не правятся.
3. Свет и цвет стен **общие** для всех вкладок. Блок этих настроек есть в каждой вкладке и меняет одно и то же.
4. Сохранённые настройки из старых ключей `localStorage` **не переносим**. Новые ключи, старые игнорируются.

## Модель данных

Координаты — как сейчас на плане: мм, x — вправо, z — от входной двери к кухне, начало — внутренний угол прихожей.

```js
A = {H:2600, hallW:1200, kW:2200, kL:4750, bNiche:1200, bL:1100, eD0:84, eD1:976, ...}  // правятся только на «Планировке»
WALLS = [
  {id:'entryBear', r:[x0,x1,z0,z1], rooms:['hall','bath'], holes:[[from,to,top,sill]]},
  {id:'kitWall',   r:[...],          rooms:['kitchen','bath','hall']},
  ...
]
ROOMS = {                     // локальные координаты комнаты = план + сдвиг (поворотов нет)
  hall:    {origin:[0, 0]},
  bath:    {origin:[xL, 0]},  // на плане уже есть bx()/bz()
  kitchen: {origin:[xL, kZ1]},
}
VIEWS = {
  plan:    {rooms:'all',       fade:{entryBear:'-z', leftBear:'-x', ...}},   // «Разрез»: прячутся внешние стены
  kitchen: {rooms:['kitchen'], frame:[x0,x1,z0,z1], fade:{...}},
  bath:    {...},
  hall:    {...},
}
```

- **`rooms`** — флажок: на каких вкладках видна стена. На «Планировке» видны все.
- **`frame`** — прямоугольник вида. Стены обрезаются по нему в данных, а не clipping-плоскостями: все стены — прямоугольники вдоль осей, так что достаточно пересечь прямоугольник стены с рамкой и обрезать проёмы. Торцы остаются закрытыми, а контуры (`wallOutline`) и следы на полу считаются по обрезанному прямоугольнику.
- **`fade`** — с какой стороны камеры стена прячется в режиме «Разрез». На «Планировке» — как сейчас в `wallRule()`: прячутся только внешние стены. Для комнаты сторона по умолчанию вычисляется (стена прячется, когда камера по другую сторону от пола комнаты), в `fade` записываются только исключения.
- **Мебель** строится как сейчас, в локальных координатах комнаты: `computeParts(p)` не меняется. В сцену она ставится группой со сдвигом `origin`.

## Структура исходников

`build.js` собирает одну страницу приложения: `<script src="js/…"></script>` заменяется содержимым модуля, по тому же принципу, что сейчас подставляется `decors.js`.

```
src/shell.html           шапка и вкладки; один iframe с приложением, вкладка = вид
src/app.html             разметка, стили, контейнеры панелей
src/js/apartment.js      A, WALLS, ROOMS; обрезка стен рамкой; двери; окно
src/js/engine.js         renderer, сцена, орбита/панорама/пинч, цикл, 5 режимов стен
                         (Монолит/Ряд/Разрез/Скелет/Контуры), свет, цвет стен, тема,
                         мини-вид, размерные линии
src/js/furniture.js      общее для шкафов: текстуры декоров, boxGeo, отделка FIN,
                         выбор и контекстное меню, анимация дверец, деталировка, сохранение
src/js/views.js          VIEWS и переключение вида
src/js/rooms/kitchen.js  computeParts, build, техника, размерные линии, камеры, панель
src/js/rooms/bath.js
src/js/rooms/hall.js
src/panels/*.html        разметка панели каждой вкладки
```

Маленькие файлы заодно избавляют от правила «не читать hall/bath/kitchen целиком». CLAUDE.md обновляется на последнем этапе.

## Переход между вкладками — перелёт камеры

Сцена одна, поэтому переход — это перелёт, а не подмена картинки. Он длится около 0.8 с. Все изменения ведёт один общий прогресс `p` от 0 до 1, так что камера, стены, мебель и тени двигаются синхронно.

1. **Панель** переключается сразу по клику: панели всех вкладок лежат в DOM, видна одна. Хэш в адресе меняется (`#kitchen`).
2. **Камера** летит к ракурсу новой вкладки. При первом входе — стандартный ракурс вкладки (у кухни «3/4»); пресеты задаются в локальных координатах комнаты плюс `origin`. Потом — туда, где вкладку оставили. На «Планировку» камера возвращается в последнюю позицию на плане. Поворот выбирается по короткому пути, как сейчас в `setView()` плана.
3. **Стены:**
   - стены, которых нет в новом виде, опускаются в пол: высота среза → 0. Это тот же механизм `scale.y`, что у ползунка «высота среза»;
   - стены, которые появляются, поднимаются из пола;
   - общие стены остаются, а их высота среза переходит от значения старого вида к значению нового (план в режиме «Ряд» 10 % → кухня 100 %: стены дорастают);
   - рамка `frame` сужается или расширяется от старой к новой (у «Планировки» рамка — вся квартира). Куски стен — коробки, поэтому обрезка по длине — это масштаб и сдвиг куска, без пересоздания геометрии. Следы на полу ведут себя так же. Контуры `wallOutline` пересчитываются в конце перелёта, а во время него скрыты;
   - режим стен (Разрез/Скелет/…) переключается в начале; правила `fade` берутся у нового вида.
4. **Мебель.** У каждой комнаты свои материалы (`mats`, `applyMaterials()`). Мебель уходящей комнаты тонет под пол: горизонтальная плоскость отсечения на её материалах, `renderer.localClippingEnabled`. Мебель новой комнаты поднимается. Запасной вариант — плавное растворение (opacity) материалов комнаты; выбираем по виду на этапе 4.
5. **Солнце.** Направление общее. Цель солнца и рамка теневой камеры плавно переходят от рамки старого вида к новой: на «Планировке» ±4.6 м, в комнатах плотнее, чтобы тени были чёткими. Тени не прыгают.
6. **Размерные линии** гаснут в начале, а линии нового вида появляются в конце. Выбор мышью на время перелёта выключен.
7. **Прерывание.** Клик по другой вкладке посреди перелёта запускает новый переход от того, что сейчас на экране, поэтому переход интерполирует от текущего состояния, а не от настроек старого вида. Если потянуть мышью, камера отдаётся орбите, а стены доигрывают переход.
8. **Без перелёта:** первая загрузка сразу по хэшу и `prefers-reduced-motion`.
9. **Между комнатами** (кухня → прихожая) перелёт прямой. Если камера некрасиво проходит сквозь стены, в середине пути добавляется «подскок» (увеличить `r`/`phi`).

Устройство в коде (`views.js`):

- `VIEWS` — статическое описание вида: `rooms`, `frame`, `fade`, пресеты камеры;
- состояние вида — камера, режим и высота среза, рамка;
- `transition` — `from` (что сейчас на экране: камера, рамка, высота каждой стены, видимость мебели по комнатам, рамка теней) и `to` (вид-цель). `loop()` вызывает `transition.step(dt)` перед нынешним кодом среза стен. После `p = 1` управление возвращается обычной орбите (`cam`/`goal`).

Прочее при смене вида:

- **двери и окно** видны вместе со своей стеной;
- **выбор мышью** — raycast только по объектам активного вида. Raycaster в three r128 не учитывает `visible`, поэтому фильтр — по видимости предков или через `layers`;
- **блок «Свет и цвет стен»** — общий компонент в панели каждого вида;
- **мебель** комнаты строится лениво: при первом входе в комнату или при включении «Шкафов» на «Планировке». Старт не медленнее, чем сейчас.

## Этапы

Каждый этап — один коммит в ветке `single-model`. После каждого запускается `npm run build`, и `index.html` работает. Пока комната не перенесена, её вкладка остаётся старым iframe: shell держит и приложение, и старые страницы.

1. **Модель квартиры — отдельный модуль.** Вынести `A`, `WALLS`, `ROOMS` из `src/plan.html` в `src/js/apartment.js`, дать стенам `id` и флажки `rooms`, комнатам — `origin`. Научить `build.js` вставлять модули. План строится из модуля, на вид ничего не меняется.
2. **Приложение с движком и видом «Планировка».** `src/app.html`, `engine.js` и `views.js` на основе `src/plan.html`: у него уже координаты квартиры и все режимы стен. Правила `fade` переходят из `wallRule()` в вид. Появляются состояние вида и каркас `transition`. Блок «Свет и цвет стен» становится общим компонентом. В shell вкладка «Планировка» открывает приложение; `src/plan.html` удаляется.
3. **Размеры стен на «Планировке».** Слайдеры для `A`: прихожая, санузел, кухня, проёмы, окно, потолок, толщины стен. Сохранение в `apt-model-v1`. Ограничения, чтобы стены не пересекались. Блок «Что заложено, мм» остаётся сводкой.
4. **Кухня.** Общий код комнат выносится в `furniture.js`, кухня — в `rooms/kitchen.js`. Техника (мойка, варочная панель, посудомойка, духовка, вытяжка, холодильник) переезжает из `buildWall()` в мебель. Стены берутся из модели: вид `kitchen` с `frame` вместо `L`. `W` и `H` — только чтение. Вкладка «Кухня» открывает приложение; `src/kitchen.html` удаляется. Здесь появляется первый настоящий перелёт «Планировка ↔ Кухня»: обрезка рамкой через масштаб кусков стен, подъём и опускание стен, мебель тонет или растворяется (выбрать по виду), плавная рамка теней.
5. **Санузел.** `rooms/bath.js`. Стенки ниши и короб берутся из модели, инсталляция и унитаз — мебель. `src/bath.html` удаляется.
6. **Прихожая.** `rooms/hall.js`. Одна входная дверь — из модели; `Lw`/`Rw` выводятся из проёма; `Sd` становится рамкой вида. Прихожая идёт последней, потому что она самая связанная. `src/hall.html` удаляется.
7. **Шкафы на «Планировке».** Переключатель «Шкафы» в настройках вида. Как показывать шкафы в режимах «Ряд» и «Контуры», решим на этом этапе.
8. **Уборка.** Shell без старых iframe; README и CLAUDE.md: новая структура `src/` и правила чтения файлов.

## Проверка (в Node, без браузера)

- После каждого этапа: `npm run build`, затем в Node проверить, что изменения попали в `index.html` (новые модули есть, удалённых страниц нет).
- **Модель:** выполнить `apartment.js` в Node и сверить с нынешними числами плана: `BOX` (габариты по внешним стенам) и прямоугольники всех `WALLS` совпадают с версией до переноса.
- **Мебель:** `computeParts` в комнатах чистая (не использует THREE). В Node сравнить список деталей старой версии (из git) и новой при параметрах по умолчанию — должны совпасть один в один. `W`/`L`/`H`, взятые из `A`, дают те же значения.
- **Обрезка стен:** в Node вывести обрезанные прямоугольники стен для каждого вида и сверить с нынешними стенами комнат. Например, левая стена кухни: 200 мм толщиной, 1350 мм от кухонной стены.
- Визуально результат смотрит пользователь в `index.html`.

## Риски

- **Прихожая** — самая связанная часть (дверь, облицовка, проём), поэтому она переносится последней.
- **Свет:** сейчас у комнат свои направления солнца по умолчанию (кухня az 39, план −35). С общим светом вид комнат немного изменится.
- **Перелёт:** обрезка по длине через масштаб работает, пока у стен нет текстуры. Сейчас стены однотонные; если появится текстура (плитка), нужно будет пересоздавать геометрию в конце перелёта.
- **Производительность:** вся мебель будет в одной сцене. Скрытые группы — `visible=false`, кэш текстур декоров один на всё приложение. Зато вместо 4–8 WebGL-контекстов останется один.
